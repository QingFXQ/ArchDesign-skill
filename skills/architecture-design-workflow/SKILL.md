# 建筑设计与图纸制作

按本 Skill 对应内部参考完成本项检查。

## 开工：把当前任务变成可执行依据

读取项目现有PROJECT.md、BRIEF.md、任务书及最新反馈，核实际源文件和活动文档。新项目缺记录时建立简短记录，已有项目从最新有效状态继续。先核本次需要的工具，不把连接所有软件作为开工条件。

明确四种不同性质的信息：适用法规和标准、课程交图要求、用户偏好、本次方案数值。不得把示范工程的尺寸、某次作业纸幅、身份或层高写成通用规范。涉及规范结论时查当前适用地区、版本及官方来源；未经核查不声称合规。

制作依据至少说明：
- 要交的图、纸幅方向、张数、允许比例、主图占比、源文件格式与截止。
- 哪份文件分别控制场地、体量、各层平面、层高、交通、立面；哪个局部被最新批注替代。
- 冻结范围、可以协调的范围、尚未知且影响下一步的关键问题。

按对象确定优先关系，不能一概“最新文件覆盖全部”或“OBJ永远优先”。未给项目名就登记未提供，禁止擅自给方案起名、翻译命名或添加概念口号。图名使用准确的用途名称。

用户授权连续制作后自主推进可恢复工作。关键矛盾集中询问，其他独立部分继续；已答过的问题不重复问。用户要求先规划或先收集反馈时，只交对应材料，不启动依赖其决定的制作。不要自动创建目标、定时任务或多人写入。

## 从当前成果选择起点

| 当前成果 | 先做什么 | 下一步依据 |
| --- | --- | --- |

## 1. 先把建筑设计成立

以建筑学理论指导实际创作：按需读[建筑空间设计](references/methods/concept-design/spatial-composition-theory.md)（单空间、多空间、体形与构成）、[园林空间设计](references/methods/concept-design/garden-space.md)（藏露、视线、序列）、[草图与建筑表现](references/methods/concept-design/sketch-and-representation.md)（快速视觉推演）及[类型设计资料](references/methods/concept-design/building-type-study.md)（功能与空间原型）。审美与精神目标可独立发起设计实验，随后与实用和技术条件协调；先用最低必要精度推敲真实几何与空间，不把概念研究变成报告或测试数量竞赛。

概念发散、方案创作或空间品质返修时，按需读[建筑创作工作台](references/methods/concept-design/design-studio.md)，再按具体问题选择[空间与构成原型](references/methods/concept-design/spatial-patterns.md)及[经典案例转译](references/methods/concept-design/precedent-transfer.md)。先用平剖、空间原型和真实模型对照推敲建筑本身，再推进详细房间排布及制图；技术校验不能代替审美与空间判断。已选定方案则集中解决其实际设计问题，不机械扩展案例或生图。

### 尺寸、场地与体块
核单位、轴向、可靠尺寸、至少三个分散锚点、旋转中心及±0.000，记录软件间变换。导入、恢复和排版不能重复调头或缩放。纸面旋转与真实模型坐标分别处理；图形与真实北针一致，标注文字保持可读。

区分环境外框、用地边界、高低地轮廓、各层外墙、主轴、悬挑和屋面。不得以单面或总包围盒代替建筑尺寸。屋顶结合投影、立剖和高程判断，考虑微坡面，防止漏顶、封洞或虚构连接条。

场地设计实际连接道路、各类入口、室外梯、坡道及湖岸。回填和阶地形成连续面、收边、踏步和步行联系。停车先画通车道、转弯、入口出口及人行，再布车位；箭头不能代替真实道路或穿过车位。

### 功能、交通与结构
先按功能、房间尺度、体量、主要跨度与参考工程决定轴网和结构概念，再展开柱墙；不随机撒柱再凑墙。允许有设计依据的偏轴和悬挑关系。钢柱／RC柱及截面选择要有说明，课程结构概念不冒充结构验算；不为美观盲删承重支承。

公共、后勤、书流、夜间及地下联系按本任务需要组织；开放楼梯与封闭疏散核分别处理。逐层对照平面差异，核挑空、平台和玻璃边界，不把相似楼层直接当作相同。

面积和容量按阶段做必要核查，区分目标、估算与实测，区分建筑面积、楼板面积、净面积。用户明确停止面积驱动改案后不擅自重启；未知差额如实记下。家具解决穿墙、压门、堵主路等问题，不把逐椅优化变成主任务。

遇到场地、体块、交通或空间组织的具体矛盾时，用内部工具接入原有方案设计库：`python scripts/resources.py design --query "高差台地与滨水公共活动" --mode lexical --limit 3`。auto／semantic／hybrid使用原库既有能力；lexical明确只是文字检索。命中后读来源平剖和图像，把可迁移方法在本项目模型中试出，并记采用／淘汰理由；不能用案例数量代替设计。

## 2. 用可出图的原生对象制作工程图

按当前类别／宿主／版本检索真实工程资产。索引、RVT／RFA与方法说明分别核实；在工作副本试用，不升级保存原资产。路径由本地资源配置提供，不假定仓库自带数据库。

工程方法用`python scripts/resources.py engineering --query "门切不开墙" --software revit --limit 3`查既有操作卡；原生文件用`python scripts/resources.py revit --query "窗" --asset-kind family --revit 2021 --limit 3`查实际数据库。年份须替换为当前真实宿主。具体RVT／RFA类型、预览与工作副本处理见内部[资源接入](references/resources.md)，不重新建库。

先做含柱墙板、门窗真洞口、交通和标注的代表区，导出一张平面及能暴露空间的剖面，实际看图后扩展。门窗的符号、洞口与三维一致；像门的窗开启线先修显示，真门遗漏和重复另修。族已切墙时不再盲加重复Opening。

楼梯核起终标高、踏步、平台、净空、洞口和逐层接通。跨层对象按真实几何与底顶约束检查，不能凭LevelId或数量判断有无。剖面穿重要空间，关联平面剖切位置；立面核观察面和近远裁剪，避免把视图错误当成建筑错误。

重复对象用共享定义和稳定标识更新。一个活动文档一个写入者；重要变更有恢复点。失败回滚，Pending不当成功，超时先查真实对象、事务和模态状态，不盲重放、不统一吞警告、不强杀用户进程。

具体宿主操作与失效模式按需读[原生制作与模型一致性](references/production.md)。

## 3. 同版模型、表现和分析

工程图、Blender／SU和图像保留同版来源及映射。导出对象名可能截断，用稳定ID映射并核缺失；几何匹配要检查歧义。建筑修改同步相关模型和图纸；纯材质调整不重建全楼。

先选真实空间亮点，再选相机和表现投入。AI从真实基底润色材质、光影、植栽和人物；不得增加／删除楼层、结构、门窗、屋面开口、入口或道路。照片修好不等于模型已改；底图有错先回模型修。总平优先真实可校准正投影，AI辅助自然材质时保护道路和出口等几何位置。

分析图解释真实设计，不按数量凑版。爆炸图用独立模型副本真实分层，切分跨层构件，表达关键功能及实际连续路径，图例和层名清楚。体块推演的每步对应实际操作；没有计算不编性能模拟。

## 4. 从参考到版面，而非把图片排齐

先读[案例、构图与风格控制](references/presentation.md)。用户给定参考优先，本地案例库随后匹配，新的网络检索按需。公开学校作品页、局部配图和作品集跨页都不能自动算完整A1／A0示范。

本地检索示例（脚本仅做匹配，不给美感打分）：
```text
python scripts/cases.py --query "竖向 景观 爆炸" --limit 6
python scripts/cases.py --ids CASE_0007 CASE_0018 --contact preview.jpg
```
使用skill目录内的实际脚本路径。目录通过`--catalog`、环境变量`ARCH_LAYOUT_CATALOG`或本地资源配置提供。找不到时报告缺失并使用用户提供参考，不编造已检索结果。

打开候选整套图，比较主图占位、视线、图组、长立剖、背景衔接、字级与留白，明确借用和舍弃。用户整体认可的案例范围可以广泛保留，单个执行者不擅自缩成唯一风格；字体、小字、作品名和装饰不随构图照搬。

按最终毫米放入真实图件缩略图与必要文字，先解纸幅容量、比例、标题带和主次。复杂整套任务可做两种有区别的低成本预案；用户已有明确构图时直接沿它深化，不固定每次两案或逐阶段审批。

禁止用无意义小字、装饰英文、重复说明、空泛口号填空白。主标题只用用户给定名称；尺寸、轴号、图名、必要说明和身份信息保留实际用途。不能为了满版虚构分析、指标或设计结论。

字体和画风在批量精排前形成项目样式：技术字与图名字体、字号层级、线宽、标题带间距、材料色、环境色、分析语义色和光照方向。字体家族通常控制一至两个，作为建议而非国标断言；项目已有仿宋等要求则沿用。用真实文字做样张，不加无意义副题。

先将主效果、总平、一张立剖和分析图并置检查统一性，再扩展整套。共享材料、色温和色彩逻辑，但保留不同图种的信息分工。结构切面重、投影轻，普通墙玻璃不统一涂黑。技术图不能因氛围处理丢失尺寸或洞口。

图纸原始比例、最终放置尺度和图名一致；禁止分轴拉伸或只改比例标签。含标注边距的整图不能直接当建筑实体范围配准。文本、图名及双横线保留各自空间；有效PPI与字高按最终纸面检查。

## 5. 交付PDF与真正可编辑的源文件

交付物按任务约定；PSD需明确含哪些可编辑内容，按[可编辑交付与PSD验证](references/editable-delivery.md)执行。每板独立文件，文字为文字层、图件独立、照片优先智能对象、流线图例与背景分组。技术图内部建筑修改回原生源，不承诺在PSD内编辑BIM墙体。

Photoshop未检出或未测试时如实标注。先做文字／图片／蒙版／替换小样并在目标宿主打开验证，不能把改扩展名、扁平图层或中间格式宣称为已验证PSD。源文件与打印PDF的字体、裁切、位置和比例一致；超出PSD容量再明确采用PSB，不静默替换格式。

每轮真正查看：
1. 整套：各板分工、连续性、重复图及整体风格。
2. 整板：唯一或明确层级的焦点、阅读顺序、密度、留白、背景与图组关系。
3. 打印局部：字、线、尺寸、轴号、图名、双横线、图例、剖切和裁切。
4. 跨图：平面—立面—剖面—三维一致，效果与分析没有新增建筑事实。

按产物类型分别取证，不让所有项目过同一套软件检查：PDF 核实际纸幅、布局、当前版本与整板／打印评审；DWG 核 CAD 保存重开、图层、尺寸与可编辑性；RVT 核保存重开、对象与模型状态；BLEND 核保存重开、对象与场景；PSD 核图层结构、文字编辑、置入内容与保存重开。需要哪几项由任务书和显式声明决定，缺证据拒绝交付，不适用须写明原因。自动检查不能当宿主验证用。

产物按 `active`／`superseded`／`archived` 管理：新版本用 `--supersedes` 或在新修订登记来替代旧产物，旧记录保留路径、SHA256、版本与替代关系，只有 `active` 参与门禁。图件改动后原有评审与宿主验证即失效，必须重新看图、重新实测。

```text
python scripts/project.py --root PROJECT artifact --path boards.pdf --kind pdf --supersedes draft.pdf
python scripts/project.py --root PROJECT review --kind visual --evidence review.md --note "整板与打印局部" --scope whole_board --scope print
python scripts/project.py --root PROJECT review --kind host --check cad_reopen --artifact plan.dwg --evidence cad-log.txt --note "CAD 2024 保存后重开"
python scripts/project.py --root PROJECT deliver
```

机械检查可运行`python scripts/check_layout.py layout.json --pdf boards.pdf --report checks.json`；输入约定和例子见[检查与反馈](references/verification.md)。它能检查纸幅、边界、显式重叠、比例、必要图件和声明的PPI／字高，不能证明美感、模型正确或用户验收。

所有图等权、图名碰撞、大片无意义空白、主图无焦点或与用户参考没有关系时，回构图阶段重排，不靠加字、花草或改几个间距宣布完成。

保存当前有效源、PDF、预览与可选单图包，历史另存不删除。记录来源修订、实际检查和未验证项。运行日志、自动化代码、检索台账不进入展板。

## 6. 改进与知识积累

用户反馈先定位输入、模型、宿主对象、视图、图像或版面的根因，再只重做受影响链。记录问题、证据、有效修复与适用范围。优先完善脚本、检查与失败样例，再改本skill的对应规则；不无限追加提示词。

需要结构化记录项目问题时，可用 `python scripts/feedback.py --root PROJECT report …` 登记，按 `reported → reproduced → diagnosed → fixed → regression_verified` 流转；根因未复现就写 `suspected` 或 `unknown`，不写成已确认。修复应关联可运行的回归测试。单次项目的尺寸、纸幅、作品名和偏好留在项目记录，不写进通用规则。

五种状态分开写：自动检查通过、执行者看图评估通过、宿主验证通过、用户确认通过、尚未验证。用户已认可风格不代表所有图件正确；宿主运行成功不等于规范合规。

### 专业知识积累与共享

1. 设计过程中主动关注用户、教师和其他设计参与者提出的专业建议、评图意见、设计理念、绘图标准和审美判断。
2. 自主判断哪些内容具有跨项目复用价值；结合具体语境提炼经验，保留必要依据与适用条件。
3. 整理前先读 [`references/knowledge/`](references/knowledge/README.md) 中已有的 Markdown，避免重复；存在分歧时保留不同观点和评价依据。
4. 把有价值的经验直接写成自然语言 Markdown，不调用专门的知识处理脚本，不建 JSON 记录、状态机或审批流程。
5. 对用户已经授权公开共享的内容，使用当前环境已有的 GitHub 工具提交 Issue 或 Pull Request；缺少权限时先保存在本地，不能假称已上传。
6. 新的设计任务开始时，主动检索相关知识，并结合当前场地、功能、设计目标和现行规范判断是否适用。
7. 使用经验后根据真实反馈修正知识；不把个人审美偏好或一次评图意见直接当作普遍规则。
8. 不上传私人项目资料、未授权图纸、客户信息或敏感数据；未经授权不得公开用户内容。
9. 所有知识收集、判断、归纳与应用都由执行端直接完成，禁止引入专用知识处理程序。

规范结论写清可核实的出处；设计经验保留项目背景；审美判断保留评价依据与适用语境。不编造规范、案例或评图意见。写法见[知识库说明](references/knowledge/README.md)。

本地资源、宿主差异与配置方式见[资源与工具接入](references/resources.md)。本skill维护与建筑项目执行分开，不能为维护skill顺带修改活动RVT／BLEND或其他项目。
