# revit-model-hardening — 绘图前的模型整理与软件故障处理

## 0. 范围

**只做两件事。** 涉及空间设计时回到方案深化，仍由当前执行者协调。

| 做 | 不做 |
| --- | --- |
| 只读审计：把模型里到底有什么量清楚 | 判断空间组织是否合理 |
| 图形层级：线型线宽从一刀切变成四档 | 判断功能分区对不对 |
| 墙体类型语义：内外墙、厚度的类型命名 | 决定每个房间该多大 |
| 孤立构件判别：哪些能删、哪些不能删 | 调整面积分配 |
| 出图前核验：改完真的对了吗 | 评价立面比例、材料、审美 |
| Revit MCP 故障诊断与恢复 | 替代规范审查 |

判断标准：**如果一个动作会改变空间关系、面积分配或形式，它不属于本参考。** 本参考 的写入应当是零几何改动，或改动前后都有可比的量测证据。

## 2. 三种可量化的坏状态

不要靠看截图判断。量这三个数。

| 状态 | 量化判据 | 实测实例 |
| --- | --- | --- |
| **层级塌陷** | 统计全部模型类别的 `GetLineWeight`，投影线众数占比 >90% 且众数为 1 号 | 119 个类别中，墙/柱/板/门窗/楼梯/家具/轴网的投影线**全部 1 号**；剖切线只有 3 档，最粗档 b 缺失 |
| **语义缺失** | 类型名含 `UNASSIGNED`/`WIP`/`UNRATED`/`TEST`，或「外墙」类型根本不存在 | 313 段墙类型名 `B07H_200mm_PARTITION_RATING_UNASSIGNED`；94 扇窗中 **39 扇挂在 PARTITION 类型上** |
| **构件漂浮** | 不围合房间的墙 >15%，或出现跨全楼高（>20 m）的孤立短墙 | 175 段 / 675.6 m；其中 1 段 2.4 m 长、24.0 m 高 |

## 3. 五个工作包

按顺序做。每包独立验收、独立保存。

### 3.0 P-AUDIT 只读体检

一次调用取一类数据，不要合并成大查询。必须取到：

1. 标高表 + 轴网（名称、高程、是否废弃）
2. 墙体按「类型 × 宽度 × 是否围合房间 × 是否有门窗」分组计数与总长
3. 楼板按层计面积
4. 房间按层计数量与净面积；零面积房间数
5. 门窗/楼梯/家具计数与类型分布
6. 警告列表（数量 + 描述）
7. **对象样式**：全部模型类别的 `Projection` / `Cut` 线宽 + 线型图案
8. 磁盘 SHA256 与 `IsModified`

先建恢复点，再体检。恢复点命名 `_backup/<原名>_<YYYYMMDD_HHMM>_<用途>.rvt`，校验前后 SHA 一致。

代码模板见 `references/revit-api-field-notes.md` §6。

### 3.1 P-GRAPHIC 图形层级

**目标**：从一刀切变成 `b / 0.7b / 0.5b / 0.25b` 四档。

- 只有**剖切线**承担层级主责任；投影线统一归到中间档，不要逐类别微调
- 轴网必须是**细单点长画线**，不是实线
- 家具是单一类别，对象样式只能给一个线宽；要细分必须走**视图过滤器**或**族内子类别**
- 改完必须在视图里**打开线宽显示**再看

完整映射、实测线宽表与验算见 `references/graphic-hierarchy-revit.md`。

**验收**：缩到 25% 仍能一眼分出「骨架 / 围合 / 家具」三层。

### 3.2 P-WALLTYPE 墙体类型语义

**目标**：每段墙都能从类型名读出「内外 + 厚度 + 材料 + 等级」。

命名模板：`<内/外/防火>墙-<厚度>-<材料>-<等级或耐火极限>`

- `外墙-200-加气砌块-A3.5` / `内墙-200-加气砌块-A2.5` / `内墙-100-加气砌块-A2.5`
- `隔断-50-卫生间隔板`（此类应关掉「房间边界」）

做法（每批 ≤3 段，逐批验收）：

1. 先建**外墙类型**，把挂在错误类型上的门窗宿主墙迁过去（**窗宿主是最可靠的“这段墙是外墙”的证据**）
2. 再重命名内墙/隔断类型
3. 最后按功能房间给围合墙套防火类型（耐火极限由规范决定，不由本参考 判断）

**内外墙判定优先级**：有窗 → 外墙；被 1 个房间引用 → 外墙或分户墙；被 ≥2 个房间引用 → 内墙；不被引用 → 见 §3.3。

**验收**：墙总数不变、宽度分布不变、门窗宿主全部落在语义正确的类型上、警告 0。

> 常见误区：把「重命名类型」当成「改了构造」。改名前后的几何完全一致。构造分层（砌块/保温/抹面）是另一件事，**会改变墙厚**，必须等立面收口定了再做。

### 3.3 P-ORPHAN 孤立构件判别

**「不围合房间」≠「垃圾」。** 先分类，再决定。

| 类别 | 判据 | 处置 |
| --- | --- | --- |
| 卫生间隔板 | 厚 50 mm，集中在卫生间区域 | **保留**，本来就设在房间内部 |
| 带门的实墙 | 挂有门实例 | **保留**，功能性隔墙 |
| 低矮短墙 | 高度 <1 m，4 段成一组矩形 | 可删，多为试验件 |
| 墙头残段 | 与同层其他墙共线但孤立 | 可删 |
| 跨全楼高短墙 | 高度 >20 m、长度 <3 m | **保留待判**——可能是通高管井/竖向收口 |
| 重复墙 | 同层同起终点坐标 | 删多余，留一段 |

**必做一次重复检测**（按标高 + 端点取整到 mm + 端点排序分组）。没有重复，就说明孤立墙都是真实构件。

**验收**：删除 + 保留 = 原数量；房间/门窗/楼板计数不变；警告 0。

### 3.4 P-VERIFY 出图前核验

- 逐项填 `checklists/revit-hardening-checklist.csv`
- 每个「改后值」都要用**独立查询**回读，不能用写入返回值当证据
- 保存后核对磁盘 SHA256 与 `IsModified`
- 视图里实际看一眼：线宽显示打开、缩到 25%、灰度打印预览

## 4. 软件故障处理

完整坑表见 `references/revit-api-field-notes.md`，这里是必须背下来的六条。

### 4.1 单位三套

Revit API 内部长度一律**英尺**。

```csharp
double Ft(double mm) => mm / 304.8;   // 毫米 → 英尺
double Ft(double m)  => m  / 0.3048;  // 米   → 英尺
```

`NewRoom(level, UV)` 的 `UV` 也是英尺。**最常见的致命错误是从米换英尺时误用了毫米的除数**：

```csharp
// ✗ 58.7 m 被算成 0.19 ft ≈ 0.06 m，房间落到原点
document.Create.NewRoom(lv, new UV(58.7/304.8, 38.0/304.8));
// ✓
document.Create.NewRoom(lv, new UV(58.7/0.3048, 38.0/0.3048));
```

症状：房间建成但面积恒为 0，位置在原点附近。**看到面积 0 先算单位，不要怀疑墙没闭合。**

### 4.2 一批 ≤3 个构件

批量建构件会触发警告，警告变模态框就堵死队列。分批 + 每批独立验收，比一次建 50 个快。

### 4.3 批量写要自开事务并关模态

`transactionMode: "auto"` 让包装器管事务时，警告会变成模态框，UI 线程卡死，之后连只读调用都超时。

```csharp
using (var t = new Transaction(document, "batch"))
{
    var opt = t.GetFailureHandlingOptions();
    opt.SetForcedModalHandling(false);   // 警告不弹框
    opt.SetClearAfterRollback(true);
    t.SetFailureHandlingOptions(opt);
    t.Start();
    // ... 写入 ...
    t.Commit();
}
```

提交后**再读一次**面积/参数——Commit 前读到的是旧值。

### 4.4 超时先查状态，不重试、不强杀

顺序：短超时只读探活（`return new{X=1};` 30 s）→ 查进程 Responding / 有无模态窗口 → 查插件日志最新行 → **不要点重试写入**。

**严禁强杀 Revit**：插件的「服务开关」状态在正常退出时保持，**强杀会丢失**，导致下次启动 8080 不监听、必须人工再点一次。优先 `CloseMainWindow()`；无响应时先确认 `IsModified == false` 再决定。

### 4.5 端口只有一个

- **8080** = MCP socket，唯一可用
- **8088** = Revit 自带 Generative Design 的本机服务，**不是 MCP**，连它会一直超时

探活失败时不要“换个端口试试”。看插件日志的 `Socket service initialized on port 8080` 才算通。

### 4.6 活动文档守卫

API 无法切换活动文档，只能校验：

```csharp
if (!String.Equals(document.PathName, Convert.ToString(parameters[0]), StringComparison.OrdinalIgnoreCase))
    throw new Exception("Wrong active document: " + document.PathName);
```

## 5. 反例（真实踩过）

| 反例 | 后果 | 正确做法 |
| --- | --- | --- |
| 看到面积 0 就断定「墙没闭合」 | 白查两轮墙缝，真因是单位换算 | 先验算单位，再查几何 |
| 用几何推断去补房间 | 造出 35 个不在功能表里的房间，全被要求删除 | 房间名与数量以图纸明细为准，禁止几何推断 |
| 把「重命名墙类型」说成「改了构造」 | 用户以为墙厚变了，实际没有 | 明确区分「语义层」和「构造层」 |
| 批量扫 122 个房间的 `GetBoundarySegments` | ExternalEvent 卡死，只能重启 | 按层分段，一次 ≤20 间 |
| 删 175 段“孤立墙” | 会删掉 106 段卫生间隔板和 44 段带门实墙 | 先分类再删，重复检测先行 |
| 强杀 Revit 以求恢复 | 服务开关丢失，用户被迫手点 | 正常关闭，确认已保存 |
| 改了对象样式没反应就去改线宽表 | 会把全局档位改坏 | 先查视图过滤器和视图样板是否覆盖 |
