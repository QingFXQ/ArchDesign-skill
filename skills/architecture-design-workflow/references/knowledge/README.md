# 专业知识库

这里存放可直接阅读、可直接引用的建筑设计知识。没有数据库、没有字段模板、没有处理脚本：Agent 读 Markdown，判断是否适用，再把新经验写成 Markdown。

## 什么时候读

遇到相关设计、制图或排版问题时选读：

- 这条经验针对的建筑类型、规模、气候区和施工条件，与当前项目是否接近。
- 它依据的是规范条款、建成回访、评图意见，还是个人偏好。
- 当前场地、功能和使用者是否会推翻它。

不适用的经验不要硬套；适用时在方案说明里写清依据，而不是只写结论。

## 写什么

- 设计注意事项：容易出错、返工代价高的地方。
- 功能组织与空间布局：流线、分区、尺度、采光、噪声、疏散的组织方法。
- 设计理念与方法：从场地、任务书到体量和空间的操作路径。
- 审美与评价：评图意见、方案比较、材料与氛围判断。
- CAD / Revit 绘图与表达：图层、线型、标注、图名、比例、出图标准。
- 返工与修正：原方案问题、修改动作、修改后的真实效果。
- 案例中可迁移的方法：不是项目介绍，而是“换一个项目还能用的做法”。

## 怎么写

先读已有条目，确认没有重复。重复的合并，不新增同义条目；有分歧时保留不同观点和各自依据，不强行统一。

一条经验可以只有一张图和几句文字。留下出处、值得复用的做法、适用条件。已经用在项目里的，附能看出变化的图。

规范结论必须能核实到具体条款，记不清就不写条款号，标明“待核”。案例必须真实存在，不编造项目、数据或评图意见。个人审美写成个人判断，不写成“应当”。

## 怎么共享

用户明确同意公开后，使用当前环境已有的 GitHub 工具提交 Issue 或 Pull Request；没有 GitHub 账号或权限时，先保存在本地项目目录，并如实告诉用户“尚未上传”。不得上传私人项目资料、未授权图纸、客户信息或可识别的个人信息。

维护者审核后合并进本目录。合并时保留来源与适用条件，不把单次意见升级为普遍规则。
