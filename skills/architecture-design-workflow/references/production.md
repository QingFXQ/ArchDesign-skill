# 原生制作与模型一致性

从已确认阶段和设计来源接续。方案对读和待决阶段见[阶段与项目约束](stages.md)。体量实验的网格可继续作为原生制作的核对依据，墙、楼板、门洞和结构的可编辑类型仍在宿主中落实。

按当前问题读对应段落，不把全文作为每个批次的体检清单。以下是制作机制；法规尺寸、结构计算和软件接口签名仍须当前项目核实。

## 依据与设计决策

建立按控制对象划分的依据表，例如“场地：测量CAD；外形：用户OBJ；功能：最新各层PDF；层高：用户修订；局部入口：后续圈图”。同时记录允许协调的外围范围和固定坡道等例外。换了PDF不自动废弃所有OBJ约束，新的圈图不自动授权重设计整楼。

读网格时保留原件，检查单位和上轴，通过多个分散锚点与已知尺寸配准。记录源→工程→表现的变换矩阵、标高映射及采用时间。旋转某个例外构件以外的整体后，其局部坐标需反算；恢复任务时先查已采用变换，不重复执行。

外轮廓应按楼层高度区间核正投影与截面，保留悬挑、退台、斜面和洞口。严格只取法向Z为1的面会漏微坡屋顶；单个面可能只是翼部。误差按数据精度设置，不能把容差扩到掩盖设计差异。

轴网先依据功能净宽、交通核、主要空间、跨度和参考工程试排。柱墙、板边、梁与开洞共同检查；偏轴和悬挑给出可解释关系。不要用“所有墙贴柱”替代结构判断，也不要因美观直接删除支承。课程截面为方案选择，未经结构计算不标“已验算”。

入口设计先核主入口、独立报告厅入口、后勤／书流入口的到达路径与开放时段，再协调门组比例、雨篷、材料和前场。用户要求“大气”时落实到空间尺度和入口层级，不只放大门符号。室外梯、平台、人行和地下联系在同一场地关系中检查。

场地停车核接路、转弯、出入口、人行过街与无障碍联系，明确避让路缘、绿化及已占车位；不以总泊位数证明交通成立。具体无障碍、坡道和转弯数值查本项目适用要求，不将历史方案数值当通用规范。

## 工程资产的实际采用

读取本地配置中的索引与SQLite库，先检查路径与数据库表结构，再按软件版本、类别、类型、宿主和预览检索。不要臆造数据库列名。区分方法卡、工程索引、实际二进制资产和下载权限；查到索引不等于拿到了RVT／RFA。

复制资产到项目工作目录，保留原件和必要的类型目录。核单位、宿主、插入位置、尺寸、材质及平剖三维显示，小样通过才批量采用。导入网格／DirectShape、原生系统构件和载入族分别说明，不能混称完整原生BIM。

## 对象、宿主与视图

按每层最新定稿逐项比对外轮廓、隔墙、门窗位置与开启、核心筒、挑空、平台、功能名称及主要家具；保留层间差异，不用标准层复制代替对照。外围为适配已冻结体量而协调时，记录具体范围并同步相邻层、立剖和表现。

- 门窗：先核宿主、插入点、宽高、窗台、朝向及族切洞；已有空洞再加Opening可能失败。洞口不成立时回读墙体交点或剖面，不只看门符号。窗开启线可按显示规则修，但真门另行核对。
- 门窗设计：结合室内功能、立面节奏与适用要求确定窗的尺度、窗台、窗顶、采光及隐私处理；普通透明窗与卫生间等服务空间分别处理，不机械复制同一小窗。已有门在原生图纸、三维和效果中都应能对应，不能润色后漏掉。
- 楼板：外边界、挑空、楼梯洞与板厚一起核；开口不能仅画一条细线。上部凹口与屋面开口逐层分别核，不机械复制。
- 墙柱梁：核底顶约束、偏移、Z范围、重复与连续支承；LevelId、数量或类别本身不是存在／缺失判断。被剖承重对象与投影对象分开显示，非承重墙不统一黑填。
- 楼梯：按沿行走方向的剖面检查总高差、各跑、踏步、平台、出入口和净空。核墙体是否遮住真实梯段、出口是否落在平台；不能靠标签或包围盒证明连通。
- 立面：核真实观察方向、近面、远裁剪、屋面和悬挑是否处于观察范围。新体块位于观察面另一侧会出现假剖面，先修视图而非删模型。
- 地下：本层剖切范围与跨层投影分开；坡道和车道实际接路，核起终高程与转弯，保留需要表达的地下范围。

CAD同样核单位、图层、Block、真实墙断口、标注、布局视口和打印范围。离线DXF打开成功不等于目标CAD宿主验证通过。

## 自动化、批量与恢复

选择当前真实可用的专用连接、API或脚本。首次未知操作用小样或回滚试算；按对象依赖和宿主耗时设置批次，不固化某台机器“每次最多三件”等限制。重复对象共享族／组件定义，按稳定标识更新，重跑不能重复生成。

同一文档只由一个写入者操作。Start后配置能识别错误的失败处理，未解决错误回滚；不得统一DeleteWarning消除重叠等设计问题。Commit的Pending状态不当完成。命令超时后先核目标ID、事务、日志和UI模态，确认未生效再重试。

长内联代码、程序集缓存和连接超时属于版本相关机制。采用本机已验证方法，记录宿主版本与限制，不把历史端口／DLL路径／族ID写入通用规则。没有连接时推进独立准备工作，不宣称已经在宿主完成。

## 同步与来源

每次导出保存原生ID到表现对象的映射。FBX名称可能被截断；必要时用物理边界与变换匹配，但要设置容差并排查一对多歧义。被隐藏、未导出和真正被删除分别判断。

建筑修改列出受影响的模型、楼层、立剖、总平、分析及照片。先更新真实模型，换同机位底图，再润色和排版；没更新的图标为旧版，不混入当前交付。共享材质或摄影后期不应触发全楼重建。

每个重要批次回读关键尺寸、约束、宿主和保存状态，再看完整相关视图。记录实际看过哪些图及尚未验证内容，避免用日志成功替代建筑检查。

用户要求展示Blender／Revit时，核当前活动可编辑文件并在真实窗口中展示；历史截图、后台日志和AI效果图不冒充前台模型。软件启动、连接、文件打开、对象已保存和图纸实际验证分别报告。
